# Веб-чат MAX через GREEN-API

Минимальный веб-клиент для переписки с пользователями мессенджера [MAX](https://max.ru) через [GREEN-API](https://green-api.com/max). Интерфейс похож на [web.max.ru](https://web.max.ru): слева список чатов, справа переписка.

**Демо:** https://green-api-max-chat.netlify.app

## Что умеет приложение

1. Вход по параметрам инстанса GREEN-API: `idInstance` и `apiTokenInstance`.
2. Создание чата по номеру телефона получателя.
3. Отправка текстовых сообщений пользователю MAX.
4. Автоматическое получение текстовых ответов без перезагрузки страницы.
5. История переписки в окне чата.
6. Выход с удалением сохранённых credentials и истории.

Больше ничего нет: ни файлов, ни звонков, ни групп, ни поиска.

## Стек

- React 19: функциональные компоненты и хуки (`useReducer`, `useEffect`, `useRef`)
- TypeScript
- Vite
- `fetch` для HTTP-запросов, без сторонних библиотек для API и состояния
- ESLint (`typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`)
- Обычный CSS со светлой и тёмной темой (по системной настройке) и адаптивной вёрсткой

Backend не нужен: GREEN-API разрешает CORS, и браузер обращается к API напрямую.

Для деплоя на Netlify в репозитории есть `netlify.toml`: команда `npm run build`, папка `dist`, Node 22.

## Где взять idInstance и apiTokenInstance

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/registration).
2. Создайте инстанс для MAX (для тестов подходит тариф «Разработчик»).
3. Авторизуйте инстанс: в мобильном приложении MAX откройте **Профиль → Устройства → Войти по QR-коду** и отсканируйте QR-код из личного кабинета. Сейчас для этого нужно отключить пароль для входа в MAX.
4. На странице инстанса скопируйте:
   - `idInstance` — номер инстанса;
   - `apiTokenInstance` — ключ доступа;
   - `apiUrl` — хост API.

Приложение само подставляет `apiUrl` вида `https://{первые 4 цифры idInstance}.api.green-api.com`. Если в личном кабинете указан другой адрес, укажите его в блоке «apiUrl инстанса» на форме входа.

Чтобы получать ответы, проверьте настройки инстанса в личном кабинете:

- поле **webhookUrl** пустое (иначе HTTP API не отдаёт уведомления);
- включено **«Получать уведомления о входящих сообщениях и файлах»** (`incomingWebhook = yes`).

При входе приложение вызывает `getStateInstance` и `getSettings`. Если инстанс не авторизован или настройки не позволят получать сообщения, появится предупреждение.

## Как создать чат

1. Введите номер телефона в поле слева и нажмите «+». Подходят форматы `+7 999 123-45-67`, `8 (999) 123-45-67`, `79991234567` и `+375 29 123-45-67`.
2. Номер приводится к формату GREEN-API: только цифры, международный формат, 11 или 12 цифр. MAX принимает номера только с кодами стран `7` (РФ) и `375` (РБ). Российский формат `8XXXXXXXXXX` превращается в `7XXXXXXXXXX`.
3. Приложение вызывает [`CheckAccount`](https://green-api.com/v3/docs/api/service/CheckAccount/):

   ```http
   POST {{apiUrl}}/waInstance{{idInstance}}/checkAccount/{{apiTokenInstance}}
   Content-Type: application/json

   { "phoneNumber": 79991234567 }
   ```

4. Если `exist: true`, создаётся локальный чат с полученным `chatId` (например, `"10000000"`). Номер появляется в шапке переписки, после первого входящего сообщения рядом появляется имя собеседника.

**Почему `chatId`, а не `79991234567@c.us`.** По [документации](https://green-api.com/v3/docs/api/chat-id/) формат `номер@c.us` оставлен для обратной совместимости. Во входящих уведомлениях MAX собеседник определяется по `chatId`, поэтому GREEN-API советует сначала получить его через `CheckAccount` и дальше работать с ним.

## Как отправляется сообщение

- Enter отправляет сообщение, Shift+Enter переносит строку.
- Пустое сообщение и сообщение из одних пробелов отправить нельзя. Текст длиннее 4000 символов (лимит `SendMessage`) тоже нельзя, об этом предупреждает счётчик.
- Сообщение сразу появляется в чате со статусом «отправляется» (часы), затем выполняется [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/):

  ```http
  POST {{apiUrl}}/waInstance{{idInstance}}/sendMessage/{{apiTokenInstance}}
  Content-Type: application/json

  { "chatId": "10000000", "message": "Привет" }
  ```

- Ответ `{ "idMessage": "..." }` означает, что сообщение отправлено (галочка).
- При ошибке под сообщением появляется понятный текст и кнопка «Повторить».
- Сообщения уходят по очереди, чтобы получатель видел их в том же порядке.

## Как реализовано получение сообщений

Используется [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/). Весь цикл находится в хуке `src/hooks/useMessagesPolling.ts`. Он запускается, когда создан хотя бы один чат.

```text
GET receiveNotification?receiveTimeout=20   (long polling)
 │
 ├─ null — очередь пуста ─────────────────────────────► следующий запрос
 │
 └─ { receiptId, body }
      ├─ текстовое входящее из открытого чата → добавить в переписку (без дублей)
      └─ DELETE deleteNotification/{receiptId} ────────► следующий запрос
```

1. [`ReceiveNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/) — long polling: GREEN-API держит запрос до 20 секунд и отвечает сразу, как только появляется уведомление. Пустая очередь даёт `null`, и запрос повторяется.
2. Тип уведомления проверяется. В чат попадает только `typeWebhook = incomingMessageReceived` из личного чата (`chatType = user`) с текстом:
   - `textMessage` → `textMessageData.textMessage`;
   - `extendedTextMessage` (текст со ссылкой) → `extendedTextMessageData.text`;
   - `quotedMessage` (текстовый ответ с цитатой) → `extendedTextMessageData.text`.

   Статусы (`outgoingMessageStatus`), исходящие сообщения, сервисные уведомления, файлы, изображения, стикеры, реакции, группы и сообщения из других чатов в переписку не попадают.
3. Каждое полученное уведомление, даже не нужное чату, удаляется через [`DeleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/). Очередь работает по принципу FIFO: пока уведомление не удалено, следующее не придёт.
4. Запросы идут строго последовательно: следующий `receiveNotification` отправляется только после обработки и удаления предыдущего уведомления.

**Защита от дубликатов.** Если `DeleteNotification` не выполнился (например, из-за сети), GREEN-API снова отдаст то же уведомление. Перед добавлением сообщение ищется по `idMessage` в истории чата, и повтор только удаляется из очереди.

**Ошибки и остановка.**

- При сетевых ошибках и ошибках сервера показывается баннер, повтор идёт с растущей паузой: 2, 5, 10 и 30 секунд. После успешного запроса баннер исчезает.
- При `401/403` (неверные credentials) получение останавливается, в баннере есть кнопка «Выйти».
- Цикл прерывается через `AbortController`, в том числе отменяется текущий long-poll запрос. Это происходит при размонтировании компонента, выходе из аккаунта и смене credentials.

## Состояния интерфейса

| Состояние | Что видит пользователь |
| --- | --- |
| Загрузка | Спиннер на кнопках «Войти» и «Создать чат» |
| Отправка сообщения | Сообщение с иконкой часов |
| Ошибка отправки | Красная обводка, текст ошибки и кнопка «Повторить» |
| Неверные credentials | Ошибка на форме входа или баннер в чате |
| Инстанс не авторизован или webhookUrl задан | Ошибка при входе или предупреждение |
| Ошибка получения | Баннер с текстом ошибки и временем до повтора |
| Нет чатов | Подсказка в боковой панели и заглушка справа |
| Пустой чат, нет входящих | «Сообщений пока нет — ответы появятся здесь автоматически» |

## Ограничения тестового приложения

- **Credentials хранятся в `localStorage` браузера** в открытом виде: так допускает задание. Токен не выводится в интерфейсе, но он входит в URL запросов GREEN-API и виден во вкладке Network. Для production запросы нужно проксировать через свой backend.
- **Приложение забирает всю очередь уведомлений инстанса.** Уведомления, не относящиеся к открытым чатам, удаляются: иначе очередь остановится. Если к инстансу подключены другие системы, получающие уведомления через HTTP API, они их не увидят.
- Пока не создан ни один чат, очередь не читается. Сообщения собеседника, пришедшие до создания его чата, появятся после создания, если с тех пор прошло меньше 24 часов (столько GREEN-API хранит уведомления). Если в это время уже был открыт другой чат, такие сообщения будут удалены из очереди и не появятся.
- Только личные чаты и только текст. Отредактированные и удалённые сообщения не обрабатываются.
- Исходящие сообщения, отправленные с телефона или из других клиентов, в чат не попадают. Статусы доставки и прочтения не отображаются: галочка значит «принято GREEN-API».
- Номера принимаются только с кодами `7` и `375` — это ограничение GREEN-API для MAX.
- История хранится локально в одном браузере и удаляется при выходе. Загрузки истории с сервера нет.
- Приложение рассчитано на одну открытую вкладку. Две вкладки делят одну очередь уведомлений, и каждое входящее сообщение увидит только одна из них.
